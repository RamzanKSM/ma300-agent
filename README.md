# MA300 agent

Локальный bridge между С2000-BIOAccess-MA300 и фронтендом ресепшена.

```text
MA300 --pyzk/UDP--> ma300-agent --SSE--> фронтенд --HTTP--> основной backend
```

Agent получает от MA300 объект `Attendance`, публикует его в SSE и **никогда не
создаёт посещение сам**. Фронтенд использует `userId` как идентификатор карты,
вызывает обычный `POST /api/v1/admin/reception/check-ins/card`, а основной
backend находит спортсмена через `card_bindings` и применяет все правила допуска.

## Требования

- Python 3.8 или новее (на Windows 7 — Python 3.8.x, последний с поддержкой Windows 7);
- сетевой доступ с компьютера ресепшена к MA300 на UDP-порт `4370`;
- зарегистрированные в MA300 `user_id` привязаны в основной системе как карты.

## Установка и запуск (macOS, Linux)

Инструкция для Windows 7 — в разделе [«Windows 7»](#windows-7).

```bash
git clone <repository-url> ma300-agent
cd ma300-agent
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python app.py
```

Агент сам читает `.env` рядом с `app.py` (другой файл — через `AGENT_ENV_FILE`).
Переменные, уже заданные в окружении, важнее `.env`, поэтому старый способ
`set -a; source .env; set +a` тоже работает.

При успешном подключении агент пишет в stderr:

```text
... INFO ma300_agent: Connected to MA300 at 192.168.1.201:4370; waiting for live events
... INFO ma300_agent: EVENT: <Attendance>: 2265 : 2026-06-25T22:46:45 (2, 0)
```

В простое при `LOG_LEVEL=INFO` лог не растёт: `time out` от `live_capture()`
(раз в `MA300_TIMEOUT_SECONDS`) пишется только на уровне `DEBUG`.

### Сторож сессии

MA300 по UDP может «забыть» сессию агента (перезагрузка терминала, обрыв сети,
брандмауэр). Раньше агент в этом случае ждал вечно. Теперь, если от терминала
`MA300_IDLE_CHECK_SECONDS` секунд (по умолчанию 30) нет ни одного пакета, агент
внутри той же сессии спрашивает у терминала время. Ответил — работа идёт дальше,
переподключения нет. Не ответил за `MA300_TIMEOUT_SECONDS` или ответил «не
авторизован» — агент пишет одну строку `WARNING` с причиной и переподключается
через `MA300_RECONNECT_DELAY_SECONDS`:

```text
... WARNING ma300_agent: MA300 session did not answer (no reply to the session check within 10 s: timed out); reconnecting in 3 s
```

Мёртвая сессия обнаруживается не позже чем через
`MA300_IDLE_CHECK_SECONDS + MA300_TIMEOUT_SECONDS` (по умолчанию 40 с). Старые
записи журнала терминала агент не запрашивает: отметки, сделанные, пока сессии
не было, на ресепшен не придут — приложите карту ещё раз.

### Только один экземпляр

Второй запуск на том же `AGENT_HOST:AGENT_PORT` сразу завершается с кодом 2 и
сообщением `MA300 agent is already running ... агент уже запущен, вторую копию
не запускайте` — ещё до подключения к MA300, сессию первого агента он не трогает.

## HTTP contract

Agent по умолчанию слушает только `127.0.0.1:8765`.

```text
GET /healthz
GET /events
```

`GET /healthz` отвечает `"status": "ok"` и состоянием терминала:

```json
{"status": "ok", "device": {"state": "connected", "lastPacketAt": "2026-10-29T12:00:05+03:00", "reconnects": 0, "lastError": null}}
```

`state`: `starting` → `connecting` → `connected`; `reconnecting` — сессия
потеряна, агент переподключается (причина — в `lastError`). `lastPacketAt` —
последний пакет от MA300 (подключение, событие или ответ сторожу).

`GET /events` — Server-Sent Events. При идентификации он отдаёт:

```text
event: attendance
data: {"type":"attendance","eventId":"...","userId":"2265","timestamp":"2026-06-25T22:46:45","status":2,"punch":0}
```

`eventId` уникален для события и нужен фронтенду для защиты от повторной
обработки. `status`, `punch` и `timestamp` сохраняются в контракте для
диагностики; решение о посещении принимает основной backend по `userId`.

## Подключение фронтенда

В `.env.local` фронтенда ресепшена:

```text
VITE_RECEPTION_WORKSTATION_MODE=CARD_READER
VITE_RECEPTION_DEVICE_EVENTS_URL=http://127.0.0.1:8765/events
```

`VITE_RECEPTION_MOCK_CONTROL_URL` для реального агента не задаётся: у него нет
endpoint'ов для имитации считываний.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MA300_HOST` | — | IP-адрес считывателя, обязательна. |
| `MA300_PORT` | `4370` | Порт MA300. |
| `MA300_TIMEOUT_SECONDS` | `10` | Timeout `pyzk`. |
| `MA300_PASSWORD` | `0` | Пароль устройства. |
| `MA300_FORCE_UDP` | `true` | Передать `force_udp` в `pyzk`. |
| `MA300_OMIT_PING` | `true` | Передать `ommit_ping` в `pyzk`. |
| `MA300_VERBOSE` | `false` | Отладочный вывод `pyzk`. |
| `MA300_RECONNECT_DELAY_SECONDS` | `3` | Пауза перед переподключением. |
| `MA300_IDLE_CHECK_SECONDS` | `30` | Через сколько секунд без пакетов от MA300 проверить сессию; `0` — сторож выключен. |
| `AGENT_HOST` | `127.0.0.1` | Адрес SSE-сервера. Не меняйте без сетевой защиты. |
| `AGENT_PORT` | `8765` | Порт SSE-сервера. |
| `LOG_LEVEL` | `INFO` | Уровень лога; `DEBUG` покажет `time out` и проверки сессии. |
| `LOG_FILE` | — | Файл лога с ротацией (1 МБ × 5). Без консоли (`pythonw.exe`) по умолчанию `logs\ma300-agent.log` рядом с `app.py`. |
| `AGENT_ENV_FILE` | `.env` рядом с `app.py` | Другой файл настроек. |

## Проверка без фронтенда

После старта проверьте здоровье процесса:

```bash
curl http://127.0.0.1:8765/healthz
```

И откройте поток событий в отдельном терминале:

```bash
curl -N http://127.0.0.1:8765/events
```

Затем приложите карту или палец к MA300. В терминале появится событие `attendance`.

## Windows 7

### Что нужно

- **Python 3.8.x** для Windows (3.8 — последняя версия с поддержкой Windows 7),
  например `python-3.8.10.exe`. При установке отметьте «Add Python 3.8 to PATH»
  или оставьте «py launcher» — установщик агента найдёт `py -3` или `python`.
- Интернет на время установки (ставится `pyzk` из `requirements.txt`).
- Папка агента может лежать где угодно, в том числе в пути с пробелами и
  кириллицей (например `C:\Users\Ресепшен\Рабочий стол\ma300-agent`). Только
  без символов `( ) & ^ % !` в пути: с ними Windows не может надёжно запустить
  скрипт от имени администратора, и установщик откажется с просьбой
  переименовать папку (например, `ma300-agent (копия)` → `ma300-agent-2`).

### Установка одной командой

Двойной щелчок по `windows\install.cmd` или в `cmd`:

```bat
cd /d C:\путь\к\ma300-agent
windows\install.cmd
```

Если Python не в PATH, укажите его явно: `windows\install.cmd C:\Python38\python.exe`.

Установщик:

1. создаёт `.venv` и ставит зависимости;
2. создаёт `.env` из `.env.example`, только если `.env` ещё нет (проверьте
   `MA300_HOST`; открыть можно Блокнотом). Сохраняйте `.env` в кодировке
   **UTF-8**: «Файл → Сохранить как… → Кодировка: UTF-8». Файл в «ANSI»
   (по умолчанию в Блокноте Windows 7) агент тоже прочитает как cp1251, но
   напишет в логе предупреждение;
3. регистрирует в Планировщике заданий задание **«MA300 Agent»**: запуск при
   входе пользователя, который сейчас вошёл в Windows (см. ниже), без пароля, `pythonw.exe app.py` без окна, без
   ограничения времени работы, не останавливается от батареи, перезапуск при
   сбое раз в минуту, вторая копия заданием не запускается;
4. сразу запускает задание, проверяет `http://127.0.0.1:8765/healthz` (Python из
   `.venv`) и печатает ответ и путь к логу.

Повторный запуск `install.cmd` безопасен: задание перезаписывается, работающий
агент перезапускается с новым кодом, `.env` не трогается.

Если Планировщик отвечает отказом в доступе, щёлкните `install.cmd` правой
кнопкой → «Запуск от имени администратора».

**Чей вход запускает агент.** Установщик берёт пользователя, который сейчас
вошёл в Windows (сеанс консоли), а не учётную запись, под которой запущен скрипт.
Поэтому, даже если в окне UAC ввести пароль другого администратора, автозапуск
останется на пользователе ресепшена — установщик напишет: «Установка запущена от
имени ПК\Администратор, а в Windows вошёл ПК\Ресепшен: автозапуск будет при входе
ПК\Ресепшен». Если определить вошедшего пользователя не удалось, установщик
предупредит, и пользователя можно указать явно:

```bat
windows\install.cmd /user:ПК\Ресепшен
```

Значения в `.env` можно комментировать как в bash: `MA300_HOST=192.168.1.201 # ресепшен`.
Внутри кавычек `#` сохраняется: `LOG_FILE="C:\logs #1\agent.log"`.

### Лог

`logs\ma300-agent.log` в папке агента (ротация 1 МБ × 5 файлов). Строки
`WARNING ... reconnecting` показывают, что сторож восстановил сессию.
Ошибки старта (нет `MA300_HOST`, неверный `LOG_LEVEL` или число, порт не
открывается) тоже пишутся туда строкой `ERROR`, после чего агент завершается —
исправьте `.env` и запустите `install.cmd` ещё раз.

### Проверка

Откройте в браузере на компьютере ресепшена `http://127.0.0.1:8765/healthz`:
`"status": "ok"` — агент работает, `"device": {"state": "connected"}` — сессия с
терминалом есть. Затем приложите карту — фронтенд получит событие.

### Брандмауэр

Если события не приходят, а в логе раз за разом `reconnecting`, разрешите
входящие UDP от терминала. Агент должен быть уже установлен.

**Проще всего:** дважды щёлкните `windows\firewall.cmd`. Если прав администратора
нет, Windows покажет окно «Контроль учётных записей» — нажмите «Да» (или введите
пароль администратора). Откроется второе окно, которое создаст правило и
напишет «Брандмауэр: разрешены входящие UDP с …». Права запрашиваются **один
раз**: если и второе окно получило их не полностью (например, UAC выключен, а
вы не администратор), оно напишет «Sign in with an administrator account…» и
больше ничего не откроет — войдите под администратором или попросите его.
Если в окне UAC нажать «Нет», первое окно напишет «Administrator rights were
not granted…», правило не меняется.

**Вручную из командной строки:** Пуск → в поле поиска наберите `cmd` → правой
кнопкой по `cmd.exe` → «Запуск от имени администратора» → в открывшемся окне:

```bat
cd /d "C:\путь\к\ma300-agent"
windows\install.cmd /firewall
```

(`install.cmd /firewall`, запущенный без прав, установит агент и в конце сам
вызовет `firewall.cmd`, который попросит права.)

Правило «MA300 Agent (UDP from MA300)» разрешает входящие UDP с адреса
`MA300_HOST` для `python.exe`/`pythonw.exe` из `.venv` и базового Python, который
их запускает. Если права не дали, правило не меняется, и скрипт об этом пишет.
Проверить: Панель управления → Брандмауэр Windows → Дополнительные параметры →
Правила для входящих подключений → «MA300 Agent (UDP from MA300)».

### Удаление

Двойной щелчок по `windows\uninstall.cmd`: снимает задание и останавливает агент.
Если было создано правило брандмауэра, скрипт сам вызывает
`firewall.cmd /remove`, который попросит права администратора (окно UAC → «Да»).
Вручную то же: `cmd` от имени администратора → `cd /d "C:\путь\к\ma300-agent"` →
`windows\firewall.cmd /remove`. `.env`, `logs\` и `.venv` остаются — удалите папку
агента вручную, если он больше не нужен.

### Не запускайте вторую копию

Пока работает задание, не запускайте `python app.py` вручную: вторая копия сразу
завершится с сообщением «агент уже запущен». Для ручного запуска сначала
выполните `windows\uninstall.cmd` или завершите задание в Планировщике.

### Ручной запуск в консоли

```bat
cd /d C:\путь\к\ma300-agent
.venv\Scripts\python.exe app.py
```

В консоли PowerShell на Windows 7 по умолчанию включено «Выделение мышью»
(QuickEdit): щелчок в окне замораживает вывод, и агент останавливается, пока
выделение не снято (Esc или Enter). Отключите его: **правой кнопкой** по
заголовку окна → «Свойства» → вкладка «Общие» (в английской Windows — «Options»)
→ снимите галочку «Выделение мышью» (QuickEdit Mode) → «ОК». Чтобы настройка
действовала для всех окон, сделайте то же через пункт «Умолчания» в том же меню.
Задание Планировщика окна не имеет и этой проблемы не знает.

### TCP вместо UDP

Если терминал поддерживает TCP, можно проверить его: `MA300_FORCE_UDP=false` в
`.env`, затем перезапустите агент (`install.cmd` ещё раз).
